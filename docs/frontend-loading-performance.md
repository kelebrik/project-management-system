# Загрузка разделов интерфейса

## Изменение

Раньше открытие приложения загружало код почти всех страниц, включая
администрирование, Jira, редактор структуры и FAQ на двух языках.
Теперь страницы загружаются через динамические импорты по мере необходимости.
Содержимое и оглавление FAQ входят в один отдельный модуль.

При открытии прямой ссылки импорт нужной страницы начинается параллельно с
авторизацией и запросами данных. Наведение мыши или клавиатурный фокус на пункте
меню заранее загружает код раздела. Импорт переиспользуется при переходе и при
повторном посещении. Переходы через меню используют React transition.

Ошибка предварительной загрузки не перезагружает текущую страницу. При попытке
открыть раздел применяется существующее восстановление устаревшей сборки:
одна перезагрузка вкладки, затем сообщение об ошибке, если файл всё ещё недоступен.
Меню остаётся доступным даже при ошибке загрузки FAQ и его оглавления.

## Контрольный замер 17 октября 2026

База сравнения: `cb371ca6cf367a19b8d8d6715bee83ab6905508b`.
Обе production-сборки обслуживались локально с gzip. Для каждой выполнено пять
прогонов в Chromium с новым контекстом браузера, без HTTP-кеша, при CPU ×4,
сетевой задержке 40 мс и пропускной способности 5 Мбит/с. API подменён одинаковой
фикстурой с одним проектом. В таблице приведены медианы, размер — в десятичных кБ.

| Сценарий | Готовность до | Готовность после | JS gzip до | JS gzip после |
| --- | ---: | ---: | ---: | ---: |
| Проекты, первое открытие | 3054 мс | 2708 мс | 753,4 кБ | 561,4 кБ |
| FAQ, первый переход | 244 мс | 398 мс | 0 кБ | 85,9 кБ |
| Проекты, возврат | 183 мс | 218 мс | 0 кБ | 0 кБ |
| FAQ, возврат | 148 мс | 165 мс | 0 кБ | 0 кБ |
| Структура, прямая ссылка | 1534 мс | 1450 мс | 523,0 кБ | 361,1 кБ |
| Гантт, переход из структуры | 148 мс | 165 мс | 144,0 кБ | 144,0 кБ |

Первое открытие проектов требует на 25% меньше сжатого JavaScript и в этом
замере готово на 11% раньше. Для структуры объём снизился на 31%, время — на 5%.
Сам основной JS-файл уменьшился с 1,32 МБ до 609 кБ без сжатия (на 54%).
Первый переход в FAQ оплачивает отдельную загрузку: около 154 мс сверх исходного
результата в этом профиле. Предварительная загрузка при наведении или фокусе
может скрыть эту задержку; замер клика не добавляет искусственного ожидания.

Готовность проектов означает появление графика и кнопки открытия паспорта,
структуры — редактируемой строки, FAQ — статьи, Гантта — полосы задачи.
После этого скрипт ждёт два кадра браузера. Размер JS — сумма запрошенных к этому
моменту файлов; отдельно считаются исходный и gzip-размеры. Это не полная
загрузка всех фоновых виджетов и не измерение скорости production API.
Время переключений в десятки миллисекунд чувствительно к нагрузке компьютера.

## Воспроизведение

Сохранить предыдущую сборку вне репозитория до пересборки, затем выполнять
замеры последовательно, без параллельной сборки или тестов:

```sh
npm run build
PERF_DIST=/absolute/path/to/previous-dist PERF_OUTPUT=/tmp/loading-before.json node --import tsx scripts/perf/measure-loading.ts
PERF_DIST=apps/web/dist PERF_OUTPUT=/tmp/loading-after.json node --import tsx scripts/perf/measure-loading.ts
```

Настройки по умолчанию: `PERF_RUNS=5`, `PERF_CPU_RATE=4`,
`PERF_LATENCY_MS=40`, `PERF_MBPS=5`. Скрипт сам запускает статический сервер,
использует только фикстуры API и закрывает браузер и сервер после замера.
JSON содержит версии браузера, параметры, все прогоны и медианы.

Проверки разделения кода и восстановления после обновления выполняются на
собранном приложении:

```sh
npm run preview --workspace @pms/web -- --host 127.0.0.1 --port 4178 --strictPort
# В другом терминале:
E2E_BASE_URL=http://127.0.0.1:4178 E2E_BUILT=1 npx playwright test tests/e2e/page-loading-built.spec.ts tests/e2e/stale-build-built.spec.ts
```
